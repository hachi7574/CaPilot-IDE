## 1. 产品定位

> **CaPilot IDE 是 Agentic IDE（Agent 编排型 IDE），不是普通 IDE。**  
> 普通 IDE（VS Code / Cursor 类）以「文件与代码编辑」为中心，编辑器、文件树、调试器是核心；**CaPilot IDE 以「多个 AI agent 的创建、编排、指挥、监控」为中心**，agent 终端（CLI TUI）与 Composer 智能输入层是主界面，文件/编辑器只是辅助查看与审查工具。

**CaPilot = AI Agent 编排工作台。**

- **CaPilot IDE**（电脑端，主体）：创建、编排、监控多个 agent；整合 agent 终端、文件资源管理器、硬件资源监视、工作树与 git 源代码控制；内置 **master agent** 统一管理标记为 **worker** 的 agent。
- **CaPilot 硬件**（ESP 触屏，遥控器）：与 IDE 实时同步的 agent 状态卡片（列表模式）、设置模式、以及**语音遥控 master**（master 模式）。物理交互仅靠 1 个 BOOT 键 + 触摸屏完成。

一句话：**在 IDE 里管好所有 agent，在桌上用一块屏和一支麦克风遥控它们。**

## 1. 需求分析

### 1.1 目标用户


| 用户画像              | 典型场景                              | 核心诉求                                 |
| ----------------- | --------------------------------- | ------------------------------------ |
| **独立开发者 / 自由职业者** | 一人扛多个项目，并行开多个 AI Agent 处理编码、调试、文档 | 在一处统一创建、指挥、监控所有 agent，不再每个都开一个终端切来切去 |
| **多 Agent 调度工程师** | 同时跑编码/测试/文档/重构多个 agent，需要相互协作     | 需要一个「master」统一调度 worker，并能按结果轻重智能汇报  |
| **AI 工作流重度用户**    | 同时使用 Claude + 其他工具，交互分散在多个窗口      | 一块桌面遥控器 + 语音，手不离键盘、不切窗口地指挥全部 agent   |


### 1.2 痛点分析


| 痛点                 | 现状                                 | 影响                      |
| ------------------ | ---------------------------------- | ----------------------- |
| **终端爆炸**           | 每个 agent 一个终端窗口，开了 5 个就要 5 个标签页来回切 | 切换成本高，状态不可见，容易错过需要介入的时刻 |
| **多 agent 协作全靠人肉** | 用户自己当「调度员」，把 A 的输出复制粘贴给 B          | 调度上限被锁死，协作全靠手动搬运        |
| **结果汇总成本高**        | 每个 agent 产出散落各处，要逐个翻日志、拼摘要         | 关键结果被日志洪流淹没，重要信息丢失      |
| **交互受限**           | 键盘/鼠标是唯一输入通道，切窗口打断深度工作流            | 手离开键盘、上下文被打断，累计时间损失巨大   |


### 1.3 使用情景

**情景 A：IDE 内 master 调度（主场景）**

```
用户打开 CaPilot IDE，总览里 4 个 agent 一目了然（2 个 worker running、1 个 waiting_input、1 个 error）。
→ 选中 master agent，输入"让编码 worker 重构 user 模块，改完让测试 worker 跑回归"。
→ master 拆解任务，逐个调度 worker，各自有独立终端。
→ 编码 worker 完成：master 返回 2 句概述 + 关键文件清单（智能返回）。
→ 用户点开编码 worker 终端，完整 diff 都在。
```

**情景 B：ESP 列表监控**

```
用户在主屏 IDE 写代码，抬眼扫一眼 CaPilot 屏：
→ 4 个 agent 卡片：状态、worker 标记、名称。
→ 发现测试 agent 停在 error，卡片闪烁。
→ 长按该卡片 → 删除并关闭 / 设为 worker / 重命名。
→ 上下滑动翻到第二页，还有 2 个 agent。
```

**情景 C：语音遥控 master**

```
用户手不离键盘，长按 CaPilot 的 BOOT 键：
→ 对着屏说话"让文档 worker 把刚才的接口写进 README"。
→ 屏幕底部字幕实时滚出识别文字，松开发送。
→ master 执行，完成后喇叭播报 2 句概述，字幕同步显示。
→ 播报中再次长按 BOOT，立即打断。
```

## 3. 目标

### 3.1 产品目标


| #   | 目标                     | 衡量标准                                            |
| --- | ---------------------- | ----------------------------------------------- |
| G1  | **Agent 管理操作时间降低 80%** | 新建/切换/指令/查看状态单次操作 ≤2s                           |
| G2  | **一站式 Agent 编排**       | 所有 agent 的创建、调度、监控、结果查看在 CaPilot IDE 内完成，无需切换工具 |
| G3  | **状态一瞥即知**             | ≤1s 掌握所有 agent 状态（IDE 总览与 ESP 列表一致）             |
| G4  | **语音驱动 Agent**         | 语音指令端到端延迟 ≤3s（说话结束到 master 开始响应）                |
| G5  | **master 智能汇报**        | worker 结果按长度/重要性分级返回（概述/标题/完整输出），且原始输出永不丢失      |
| G6  | **单键全交互**              | 仅 BOOT + 触摸屏覆盖硬件全部功能（列表/设置/master 三模式）          |
| G7  | **桌面语音遥控**             | 用户在电脑附近即可用 ESP 语音指挥任意 worker，无需接触 IDE           |


### 3.2 用户目标

- **获得「调度台」体验** — 一个 IDE + 一块屏，像混音台控制音轨一样编排所有 agent
- **不再人肉搬运** — master 负责拆解、调度、汇总，用户只下指令和审结果
- **结果不丢** — 智能返回只改变汇报粒度，worker 完整输出始终在终端里可查
- **手不离键盘** — 用语音 + 触控完成所有「遥控」操作

### 3.3 商业目标

- 建立「AI Agent 编排 IDE」产品线认知，验证多 Agent 重度用户的付费意愿
- 通过 master/worker 协作模型形成差异化，区别于单 agent 对话工具
- 收集 agent 协作行为数据指导后续版本迭代
- 为 CaPilot 硬件外设线建立用户基础（IDE 带动硬件销售）

## 4. 非目标


| #   | 非目标                                                                      | 原因                      |
| --- | ------------------------------------------------------------------------ | ----------------------- |
| NG1 | **不做 Agent 本身** — CaPilot 不训练/调优模型，Agent 能力由可插拔 CLI 运行时（如 Claude Code）提供 | Agent 能力不是我们要造的东西       |
| NG2 | **不做通用 IDE** — 不替代 VS Code 的日常开发，聚焦 agent 编排（Tauri 自建薄壳）                 | 聚焦多 Agent 管理场景          |
| NG3 | **不做移动端** — 只做桌面 IDE + ESP 硬件                                            | 明确不进入手机端                |
| NG4 | **v1 不做触控板模式、陀螺仪手势**                                                     | 交互重心在列表 + 语音，体感延后 v2    |
| NG5 | **v1 不做远场语音** — 语音为近场 PTT（长按说话）                                          | 远场降噪复杂度高                |
| NG6 | **v1 不支持无线远离** — ESP 通过 USB 连接 IDE                                       | 减少复杂度，v2 考虑 WiFi/BLE 无线 |
| NG7 | **worker 间不直接通信** — 只能经 master 调度                                        | 避免网状失控，保持调度模型清晰         |

## 6. 需求

### 6.1 产品构成总览

```
┌─────────────────────────────────────────────┐
│  CaPilot IDE（电脑端，Tauri v2 自建薄壳）   │
│  ├─ Agent 编排核心（可插拔 CLI 运行时）      │
│  ├─ Agent 终端 / 总览面板                   │
│  ├─ 文件资源管理器 + 工作树 + git 控制       │
│  ├─ 资源监视器（按 agent 维度）             │
│  ├─ master agent（worker 管理工具集）       │
│  └─ 设置 + 持久化（SQLite）                 │
└──────────────┬──────────────────────────────┘
               │ 通信：BLE-NUS（默认优先）/ USB CDC / WiFi
               ▼
┌─────────────────────────────────────────────┐
│  CaPilot 硬件（ESP32-C5 240×320 竖屏）      │
│  列表模式（4 卡片 + 翻页 + 长按菜单）        │
│  设置模式（WiFi/音量/亮度/麦克风等）        │
│  master 模式（PTT 语音 + 字幕 + 喇叭）       │
└─────────────────────────────────────────────┘
```

### 6.2 IDE 功能需求

#### I1 — Agent 管理

- **状态机**：`idle → starting → running ⇄ (waiting_input / completed / error)`，支持 停止 / 暂停 / 重启 / 删除（删除需二次确认并终止进程）
- **新建**：模板（默认 / 编码 / 调试 / 文档）+ 工作目录 + 初始 prompt；每个 agent 自动获得一个独立终端
- **角色**：agent 分 **worker**（master 可管理）与 **独立**（master 不可管理）两类；默认新建为独立，用户显式设为 worker
- **总览**：所有 agent 一屏列表，显示名称、角色标记、状态、当前动作（如"正在 Edit user.py"）、耗时

#### I2 — Agent 终端

- 每个 agent 一个独立终端视图，展示 agent 完整输入输出（**原始输出永不因智能返回而丢失**）
- 终端支持滚动、复制、清屏；文本增量渲染（agent 为真实 PTY 输出，流式转发到终端）
- 终端内容可发送回 agent（作为补充指令）

#### I3 — Master Agent 与智能返回

- **Master 工具集**（master 控制 worker 的唯一途径）：**PATH shim `capilot`（dispatch / status / report）+ Unix socket**——master 在自己的 shell 里直接敲命令派发（如 `capilot dispatch worker-1 "任务"` / `capilot status` / `capilot report "摘要"`），任何 runtime 的 shell 统一可用、不依赖 CLI 内部格式
- Master 按**名称**解析 worker 目标；指代不明确时向用户确认（"你是指 XX 吗？"）
- **智能返回规则**（详见附录）：按「失败优先、长度分级」汇报；智能返回只影响 master 向用户的汇报粒度，不影响 worker 终端

#### I4 — 文件 / 工作树 / git 集成

- 文件资源管理器：浏览、打开、编辑工作目录文件
- 工作树视图：项目目录树，agent 正在改动的文件高亮标记
- git 源代码控制：diff / commit / branch / status，可直接在 IDE 内操作

#### I5 — 资源监视器

- **按 agent 维度**显示 CPU、内存、网络占用（主视角）
- 整机总览为次要视图
- agent 超出资源上限时告警并提示终止（配合 I7）

#### I6 — 会话持久化

- SQLite 存储：agent 会话、终端历史、设置
- IDE 重启后恢复 agent 会话与终端内容
- 首次启动引导：API 认证、工作区选择

#### I7 — 权限沙箱与资源限制

- worker 工具范围默认限定在各自工作树内
- 危险操作（装包 / 删除文件 / 网络访问）需用户确认，或按 agent 配置禁止
- 每个 agent 可配置 CPU/内存上限，防止多 worker 互相拖垮

### 6.3 ESP 硬件功能需求

#### H1 — 列表模式（默认模式）

- 竖屏 240×320；顶部状态条（~40px：模式名 + 连接状态 + 未读数）
- 内容区：**4 个等高 agent 标签 + 底部固定「新建 agent」按钮**（等高，每格 ~56px）
- 每个标签显示：**状态图标 + 终端名称 + worker 标记**，第二行显示当前动作/状态文字
- **短按标签** → agent 详情视图（最近输出摘要 + 停止/重启/删除操作；完整终端在 IDE）
- **长按标签**（500~700ms，带视觉反馈）→ 弹窗：设为/取消 worker ｜ 重命名 ｜ 删除并关闭（删除需二次确认）
- **垂直滑动**翻页（4 个/页 + 页指示点）；空态显示「去 IDE 新建 agent」引导
- 新建按钮 → 引导在 IDE 完成新建（ESP 端触发 IDE 打开新建面板）

#### H2 — Master 模式

- 顶部：master 连接状态 + 模式名
- 中央：波形/留白；**底部固定 1 行实时字幕**：用户语音 ASR（左）+ master 回复文本（右），颜色区分
- **长按 BOOT = 语音 PTT**（开始录音，松开发送）；**短按 BOOT = 停止/打断播报**
- master 回复经 TTS 由喇叭播报，字幕同步滚动
- 播报中再次长按 BOOT 立即打断（barge-in）

#### H3 — 设置模式

- 列表项：WiFi 连接 ｜ 音量 ｜ 屏幕亮度 ｜ 麦克风源（板载 / 电脑） ｜ 智能返回开关 ｜ STT 引擎 ｜ TTS 音色 ｜ 字幕开关
- 所有设置与 IDE 设置双向同步

#### H4 — 模式切换（屏幕滑动）


| 当前位置      | 手势                              | 动作            |
| --------- | ------------------------------- | ------------- |
| 列表模式      | 左滑（位移 &gt;60px 且水平分量 &gt; 垂直分量） | → 设置模式        |
| 列表模式      | 右滑                              | → master 模式   |
| 设置模式      | 右滑                              | → 返回列表        |
| master 模式 | 左滑                              | → 返回列表        |
| 列表模式      | 垂直滑动                            | 翻页（不与水平切模式冲突） |


- 手势映射可在设置中自定义（可关闭任意方向切换）

#### H5 — 语音链路

- **输入**：PTT 录音 → 音频流 → IDE → STT → 文本
  - ESP 板载麦克风（默认）：16kHz 单声道 16-bit PCM 流式上传
  - 电脑麦克风：ESP 发指令 → IDE 启动电脑录音 → STT，结果回 ESP 字幕
- **输出**：IDE 端 TTS 合成 → 音频流回 ESP → 喇叭播报
- **字幕**：STT 增量结果 + master 回复文本，屏幕底部实时更新
- **端到端延迟**：说话结束 → master 开始响应 ≤3s
- **STT**：sherpa-onnx 本地流式 STT（中文流式质量 + 实时出字 + 免 C++ 构建链）；TTS 引擎可配置、默认音色可换

#### H6 — 连接与通信

- **传输**：**BLE-NUS 默认优先**（P0.5 spike 已验证吞吐）；USB CDC（串口）与 WiFi TCP/WebSocket 为备选
- **消息**：JSON 行协议
  - IDE → ESP：`agent_update / audio_start / subtitle / connection_status`
  - ESP → IDE：`touch_event / key_event / mode_change / audio_chunk / mic_request`
- **音频流**：独立二进制通道（16kHz mono 16-bit PCM）
- **心跳**：每 5s 双向心跳，超时 15s 提示断连（沿用 v2.2 M6）

### 6.4 主机端软件需求（IDE 内置）

#### S1 — 通信服务

- IDE 内建与 ESP 的通信服务（替代 v2.2 独立守护进程），开机自启、托盘常驻
- 自动发现/连接 ESP（USB 枚举 + 心跳）

#### S2 — 语音引擎

- 接收 ESP 音频流或启动电脑麦克风录音
- STT：sherpa-onnx 本地流式（中文流式质量 + 实时出字 + 免 C++ 构建链），增量推送结果给字幕
- TTS：合成 master 回复 → 流回 ESP 喇叭

#### S3 — 智能返回引擎

- 按智能返回规则表生成 master 汇报文本（概述 / 标题 / 完整输出）
- 受「智能返回开关」控制；关闭时 master 始终返回完整输出

#### S4 — 配置

- IDE 设置 + ESP 设置模式共享同一份配置（双向同步）
- 内容：agent 默认模板、worker 权限、资源上限、按键/手势映射、语音引擎、智能返回开关

### 6.5 支持的硬件平台


| 优先级    | 开发板                            | 状态                                             |
| ------ | ------------------------------ | ---------------------------------------------- |
| **首选** | **Waveshare-C5-Touch-LCD-2.8** | 32MB Flash / 8MB PSRAM，音频流 + LVGL 充裕，**硬件最完整** |
| **备选** | Waveshare-C6-Touch-LCD-2.8     | 可用，无 PSRAM，语音需省内存；**键鼠走 BLE HID**              |
| **归档** | Lceda-S3-Practical-Board       | **legacy 归档**，仅供历史参考                           |


> **C5 与 C6 板载外设一致：** 2.8" ST7789 240×320（原生竖屏）+ CST3530 触控 + ES8311 音频（麦克风 + 喇叭）+ QMI8658 IMU（v1 闲置）+ MicroSD + PCF85063 RTC + SHTC3 温湿度。
>
> **按键能力（已验证）：** 仅 **BOOT** 为软件可用功能键（C5 接 GPIO28/BOOT0，按下拉低）。**RST** 接硬件复位（CHIP_PU），**BAT_PWR** 接电源开关芯片（短按 1s 开机 / 长按 2s 关机），两者均无 GPIO、固件不可读，不能作为功能键。
>
> **最低硬件要求：** ≥2.0" 电容触摸屏（240×320 竖屏）、板载音频 Codec（麦克风 + 喇叭）、USB 供电与通信、≥1 个软件可用功能键（BOOT）、BLE（v2 无线化预留）。

## 附录

### 智能返回规则表


| 结果特征             | master 汇报形式             |
| ---------------- | ----------------------- |
| worker 失败 / 报错   | **完整输出** + 一行错误摘要（永不截断） |
| 成功 且 ≤600 字符     | 完整输出                    |
| 成功 且 600~3000 字符 | 概述（2~5 句）+ 关键文件/diff 清单 |
| 成功 且 &gt;3000 字符 | 标题级概述（1~2 句）+ 结果类型标记    |


> **约束：** 智能返回只影响 master 向用户的汇报粒度；worker 终端的原始输出始终完整保留。

### 交互模式矩阵


| 功能 \ 模式     | 列表模式                 | 设置模式   | master 模式     |
| ----------- | -------------------- | ------ | ------------- |
| **屏幕主交互**   | agent 卡片 + 翻页 + 长按菜单 | 设置列表   | 语音状态 + 底部字幕   |
| **BOOT 短按** | 进入选中 agent 详情        | —      | 停止/打断播报       |
| **BOOT 长按** | 语音 PTT（唤 master）     | 语音 PTT | 语音 PTT（录音/发送） |
| **触摸手势**    | 短按卡片 / 长按菜单 / 垂直翻页   | 点击设置项  | 点击字幕查看详情      |
| **滑动切模式**   | 左滑→设置，右滑→master      | 右滑→列表  | 左滑→列表         |


### 名词表


| 名词               | 定义                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------- |
| **agent**        | CaPilot IDE 中的一个 agent 会话 = 一个可插拔 CLI 会话（Claude Code / 其它 `AgentRuntimeAdapter` 支持的 CLI）+ 独立终端 |
| **worker**       | 被标记为可被 master 管理的 agent                                                                        |
| **独立 agent**     | 未被标记为 worker 的 agent，master 不可管理，仅用户直管                                                         |
| **master agent** | 内置的编排 agent，通过工具集管理全部 worker，向用户汇报                                                             |
| **智能返回**         | master 按结果长度/重要性分级汇报 worker 结果的功能（可开关）                                                         |
| **PTT**          | Push-to-Talk，长按说话、松开发送                                                                         |
