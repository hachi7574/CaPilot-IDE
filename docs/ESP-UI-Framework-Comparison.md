# ESP UI 框架对比：WouoUI vs LVGL

> **版本:** v0.1
> **日期:** 2026-08-05
> **作者:** HaChi + Claude
> **关联:**
> - [ESP-Firmware-Design.md](ESP-Firmware-Design.md) §10（现有 LVGL 方案）
> - [CaPilot-PRD.md](CaPilot-PRD.md) v3.0（H1–H6、三模式、"丝滑"要求）
> - [CaPilot-IDE-DevPlan.md](CaPilot-IDE-DevPlan.md) §8/§9（ESP 集成、语音链路）
> **范围:** 研究性对比 + 建议。评估对象为 [RQNG/WouoUI](https://github.com/RQNG/WouoUI)（GitHub）与 LVGL 9.2，目标硬件为 Waveshare C5 Touch LCD 2.8"（240×320 ST7789 / CST3530 触摸 / 单核 240MHz RISC-V / **无 PSRAM** / SRAM ~400KB）。

---

## 0. 结论（TL;DR）

**继续用 LVGL，不换 WouoUI。**

WouoUI 是一套「**单色 OLED + 旋转编码器**」的丝滑菜单框架，不是通用触摸 GUI。它对本项目存在四道硬性门槛：

1. **驱动层不兼容**：WouoUI 依赖 U8g2，而 U8g2 **没有 ST7789 彩色 TFT 驱动**（我核对了 u8g2 全部 `u8x8_d_*.c` 驱动清单，无 ST7735/ST7789/ILI9341 系列）。直接用不了，必须换后端并重写全部绘图调用。
2. **输入模型不匹配**：WouoUI 的交互是「旋钮旋转选择 + 点按进入」的层级菜单；C5 的核心交互是**触摸**（点卡片 / 长按 / 垂直翻页 / 横滑切模式），WouoUI 没有任何触摸概念，需自建命中、长按、滑动判定。
3. **整页缓冲模型被内存击穿**：WouoUI 每帧 `clearBuffer() → 画 → sendBuffer()` 全屏重绘，其 `fade()`/背景虚化直接按字节操作整个 `buf_ptr`。128×64 单色整页仅 1KB；240×320 16bit 整页 = **150KB**，无 PSRAM 放不下。改成条带局部刷新则这些缓冲操作函数全部失效，需重写。
4. **动态文本与 CJK 缺失**：WouoUI 菜单是编译期静态 `char*`，无换行/滚动/多行文本（实时字幕没法直接落地）；无 CJK 字体工具链（需与 LVGL 一样自己做字库，但起点更低）。

LVGL 路径在**同一块无 PSRAM 硬件上**已有可行内存预算（局部双缓冲 ~38KB + 核心 ~10–20KB，详见 §4.5），且触摸、手势、动画、CJK 子集工具链、动态文本全部内置，与「参考小智AI」生态（小智AI 的显示层正是 LVGL）一致。**「丝滑」在 LVGL 上可通过动画曲线调优达成，不需要为此换框架。**

## 1. WouoUI 调研：它到底是什么

### 1.1 事实清单（读源码核实，非道听途说）

| 项 | 事实 |
| --- | --- |
| 形态 | 每个分辨率版本是**单个 Arduino `.ino`**。`WouoUI-Lite_General.ino` 1297 行、46KB 源码，全框架无库/API/头文件拆分 |
| 后端 | **U8g2lib**。`u8g2.sendBuffer()/clearBuffer()`，每帧全屏重绘；`buf_ptr` 指向整页缓冲（128×64 单色 = 1KB） |
| 输入 | **仅 EC11 旋转编码器**（AIO/BIO 相位中断 + SW 按键），无触摸 |
| 动画 | 两行缓动 `*a += (*a_trg - *a) / (ui.param[n]/10.0f)`；可打断（动画未结束再触发时自然过渡）；`LIST_ANI/WIN_ANI/FADE_ANI` 分类权重可调 |
| UI 模型 | 静态 `MENU{char *m_select;}` 数组 + 层级栈（`UI_DEPTH=20`）+ 状态机（`S_FADE/S_WINDOW/S_LAYER_IN/S_LAYER_OUT/S_NONE`）；行类型由首字符区分：`[`标题、`-`普通、`~`数值、`+`多选、`=`单选、`#`/`$` 自定义 |
| RAM 规模 | 作者在 About 页自述 **"Ram: 20k, Flash: 64k"**（STM32F103 参考） |
| 存储 | EEPROM 写参数（11 字节校验 + 参数块），进入睡眠时写入 |
| 分辨率 | 128×128 / 128×64 / 128×32 / Lite_General（通用，仅列表类） |
| 开源协议 | **无**（README 注明"本项目不设置开源协议"，商用/借鉴需标注来源） |

### 1.2 它擅长什么 / 不擅长什么

- 擅长：128×64 级别单色 OLED 上的**丝滑列表/弹窗过渡**，动画算法极其轻量，STM32F103 20KB RAM 就能跑。
- 不擅长：彩色 TFT、触摸、动态文本、中文、复杂控件布局。所有第三方移植项目（第三方目录里 6 个）**全部是 0.96" 单色 OLED**（ESP32 例子也是 0.96" OLED），无一使用 16bit 彩色 TFT。

## 2. 特性对比矩阵（针对 C5 240×320 无 PSRAM）

| 维度 | WouoUI（原版现状） | LVGL（设计文档方案 §10） | 对本项目的影响 |
| --- | --- | --- | --- |
| 显示驱动 | U8g2；**无 ST7789 驱动**（u8g2 驱动清单不含 ST7735/ST7789/ILI9341 彩色 TFT） | 无内置驱动，`flush_cb` 交给 ST7789 SPI（现有 GFX Library 思路可复用） | WouoUI 需换后端（TFT_eSPI/LovyanGFX）+ 重写全部 `draw*` 调用 |
| 缓冲模型 | 整页缓冲 + 每帧全屏重绘；128×64 单色 = 1KB；240×320×2 = **150KB 不可行** | 局部双缓冲 2×240×40×2 = **38.4KB**；`LV_DISP_RENDER_MODE_PARTIAL` | WouoUI 的 `fade()`/虚化直接操作整页字节，条带化后失效 |
| 渲染模式 | 立即模式（每帧重画全屏） | 保留模式（对象树 + 脏矩形局部重绘） | 局部重绘对 150KB 帧缓冲的彩屏至关重要 |
| 输入 | **仅 EC11 编码器** | CST3530 → `lv_indev` pointer + 内置 swipe 手势 | C5 主交互是触摸；WouoUI 需自建命中/长按/滑动判定 |
| 手势 | 无 | `swipe_up/down/left/right`（设计文档 §10.3 已映射） | LVGL 直接满足 PRD H4 |
| 动画 | 两行缓动，可打断，分类可调；轻量 | `lv_anim` 内置多缓动曲线、对象属性动画、打断支持 | 丝滑性 LVGL 可调优达成（§4.2） |
| CJK | 无工具链；U8g2 中文字体为整字位图，无子集化 | `lv_font_conv` 子集化 3000 字入 flash（设计文档 §10.1） | 两者都要自己做字库；LVGL 有现成工具链 |
| 动态文本 | 静态 `char*`，无换行/滚动/多行文本框 | `lv_label` 动态文本、自动换行、滚动 | 实时字幕、卡片第二行动态文字是刚需 |
| 控件集 | 列表 / 单选 / 多选 / 数值 / 弹窗（仅这些） | 完整控件集（list/slider/switch/label/anim/msgbox…） | 设置模式滑块/开关开箱即用 |
| 列表翻页 | 单列单选滚动（`line_n = DISP_H/LIST_LINE_H`） | 可做卡片网格 + 垂直翻页 + 页点 | WouoUI 是单列，与「4 卡片/页 + 翻页」模型不兼容，需扩展 |
| RAM 开销 | 原版 ~20KB 总占用；但移植到 16bit 彩屏的代价在上面三行 | 渲染 38.4KB + 核心 ~10–20KB + 对象 ~5–10KB（§4.5） | 见 §4.1 预算 |
| 文档 / 生态 | 单 `.ino`、无文档、无 API、无 license | 官方文档、教程、示例、9.x 活跃维护 | 团队上手与长期维护 |
| 参考项目 | 第三方移植均为单色 OLED 菜单 | **小智AI（78/xiaozhi-esp32）显示层就是 LVGL**（`main/display/lvgl_display/` + `lcd_display.cc`），138 板型，含 ESP32-C5 平台 | PRD 参考对象与 LVGL 一致 |
| 换框架代价 | — | — | 设计文档 §10 与 `ui/` 目录结构已按 LVGL 组织；换 WouoUI = 重写 ui 层 + board flush + 字体管线 |

## 3. 分项分析

### 3.1 RAM 占用

- **WouoUI**：原版极省（~20KB 整机）。但这个数字建立在小分辨率单色整页缓冲（1KB）之上。移植到 240×320 16bit 有两种走法，都不省：
  - 整页缓冲：150KB，无 PSRAM 直接出局（设计文档强调硬约束 `BOARD_HAS_PSRAM 0`）。
  - 条带缓冲（240×40×2 = 19.2KB，与 LVGL 相同量级）：可行，但 WouoUI 的 `fade()`、弹窗虚化、以及"每帧 clearBuffer 全屏重绘"的立即模式都假设缓冲=全屏，**条带化必须重写渲染循环**，等于放弃它省内存的机制本身。
- **LVGL**：局部双缓冲 38.4KB，核心与对象 ~15–30KB，合计 UI 峰值 ~60–80KB。在 ~400KB SRAM、FreeRTOS 下与音频（Opus ~10–20KB、TTS 8–16KB、I2S DMA 2–4KB）、BLE（NimBLE）、协议队列并存，设计文档 §13 目标 **<200KB 预算、峰值 <70% SRAM**（≈280KB）有裕量。CJK 字体放 **flash**（16MB 充裕），不占 RAM。
- 结论：**RAM 上 WouoUI 的纸面优势在 16bit 彩屏上被 150KB 整页缓冲击穿；条带化后与 LVGL 同量级，且要重写。**

### 3.2 动画丝滑度（PRD 强调"丝滑"）

- WouoUI 的丝滑来自两处：轻量两行缓动 + 极低数据量的单色整页重绘。128×64 单色一帧只有 1KB 像素数据，SPI/I2C 都能轻松 60fps。
- 移植到 16bit 彩屏后，**全屏一帧 = 150KB 数据**。即便 40MHz SPI（~5MB/s 有效），整屏刷新也要 ~30ms/帧，约 30fps，且是"每帧重画全部"——这正是 PRD 想要避免的卡顿来源。要做丝滑只能局部刷新，等于重写。
- LVGL 局部渲染下：全屏级动画（列表翻页）每帧渲染 8 条 240×40 条带 + flush，约 20–30fps；**局部动画**（卡片状态变化、字幕行滚动、toast、选中高亮）只重绘脏区，感知帧率远超全屏级。动画曲线可用 `lv_anim` 的 ease 曲线按 WouoUI 手感调参。
- 结论：**「丝滑」是调优问题，不是框架问题。** LVGL 的局部重绘在彩屏上反而是丝滑的前提；WouoUI 的丝滑机制（全屏重绘）搬到彩屏上会退化成卡顿。

### 3.3 触摸

- C5 的交互核心是 CST3530 触摸：点卡片、长按（500–700ms 出菜单）、垂直翻页、横滑切模式（PRD H4）。WouoUI 输入模型是**单选择框 + 旋钮**，完全没有触摸命中、长按识别、滑动判定，需要从零实现，且要扩展它的单列列表模型才能承载"4 卡片/页 + 页点 + 垂直翻页"。
- LVGL `indev` pointer + gesture 已内置；设计文档 §10.1/§10.3 已规划触摸与手势映射，`touch_event` 上行的坐标/目标语义也与 `lv_event` 对齐。
- 结论：**触摸是 WouoUI 的空白区，是 LVGL 的成熟区。**

### 3.4 CJK 文字渲染

- 两者**都需要自己做 CJK**（LVGL 内置字体无中文，U8g2 的 U8g2 中文字体是整字位图、无子集工具链）。
- LVGL：`lv_font_conv` 生成 3000 常用字 16px/20px 子集入 flash（设计文档估算 0.5–1MB；按 16px 位图 ~32B/字 × 3000 ≈ 100KB 起，加元数据实际 200–400KB，0.5–1MB 是保守值），flash 16MB 充裕。图标用 Font Awesome 子集。
- WouoUI 若换 TFT_eSPI/LovyanGFX 后端：其字体是 4bit 抗锯齿字库，中文同样要自己用工具链生成（LVGL 的 `lv_font_conv` 也可输出 TFT_eSPI/LovyanGFX 格式），但这是一条与 LVGL 并行的新字库管线，且 WouoUI 侧无现成集成。
- 结论：**CJK 上 LVGL 有现成子集工具链与集成路径；WouoUI 不提供任何便利，起点更低。**

### 3.5 动态内容（字幕 / 列表滚动）

- master 模式的实时字幕（`subtitle` 帧，partial/final，1 行 + 滚动）是**流式动态文本**。WouoUI 的菜单是编译期静态 `char*` 数组，`drawStr` 直接画字符串，无换行、无滚动、无文本测量工具——字幕要么自己拼滚动逻辑，要么频繁整行重绘（又回到全屏重绘问题）。
- LVGL `lv_label` 天然支持动态 set_text、长文本滚动、断行，配合局部重绘，字幕行只需刷新底部一条脏区。
- 列表卡片第二行（"正在编辑 x"）是频繁更新的动态文案，同理。
- 结论：**动态文本需求把 WouoUI 的静态菜单模型排除在外。**

### 3.6 开发工作量与维护

| | WouoUI | LVGL |
| --- | --- | --- |
| 需要做的事 | 换显示后端（无 ST7789 驱动）+ 重写全部绘图调用 + 重写 fade/虚化 + 自建触摸/手势 + 扩展卡片网格模型 + 自建动态文本 + 自建 CJK 字库管线 + 补充协议事件绑定 | 按设计文档 §10 落地：`lv_port_disp/indev`、三屏幕、手势、字体子集（大部分已在文档中规划） |
| 文档 | 无（单 `.ino`，无 API） | 官方文档 + 教程 + 大量示例 |
| 协议 | 无（注明不设开源协议，商用需标注来源） | MIT |
| 参考实现 | 第三方移植均为单色 OLED 菜单，无可借鉴的彩屏触摸案例 | **小智AI** 显示层为 LVGL，含 C5 平台支持；ESP-BOX 等大量语音助手 LCD 案例 |

工作量评估：WouoUI 路线≈「参考其动画思路**自研**一个彩屏触摸框架」，比沿用 LVGL 的**落地**工作量大一个量级、风险高一个量级。

### 3.7 参考小智AI（PRD 依据）

`78/xiaozhi-esp32`（小智AI）显示层明确使用 **LVGL**（`main/display/lvgl_display/`、`lcd_display.cc` ~55KB），支持 138 个板型、含 ESP32-C5 芯片平台，OLED/LCD 表情与字幕体系都建立在 LVGL 上。PRD 的"参考小智AI"指向的正是 LVGL 路径，而非编码器菜单。

## 4. 建议

### 4.1 结论：保持 LVGL，不引入 WouoUI

理由按权重排序：
1. **驱动与缓冲**：WouoUI 的 U8g2 后端无 ST7789 驱动；整页缓冲模型在 16bit 彩屏无 PSRAM 下不可行，条带化需重写其核心渲染机制。
2. **输入模型**：C5 是触摸屏，WouoUI 是编码器菜单，触摸/手势/长按需从零实现。
3. **动态文本与 CJK**：字幕与实时卡片文案是硬需求，WouoUI 的静态菜单模型不满足；CJK 两边都要做，但 LVGL 有现成工具链。
4. **生态与参考**：小智AI 即 LVGL；文档、示例、维护齐备。
5. **已有投入**：设计文档 §10、`ui/` 目录结构、`lv_port_*` 已按 LVGL 规划。

### 4.2 内存预算（LVGL，无 PSRAM）

| 项 | 预算 | 说明 |
| --- | --- | --- |
| 渲染双缓冲 | 38.4KB | 2×240×40×2（设计文档 §10.1） |
| LVGL 核心 | 10–20KB | 事件 / 定时器 / 样式池 / 对象分配器（`LV_MEM_CUSTOM` 关，静态池） |
| 屏幕对象（三屏单实例 + 卡片/滑块/开关/toast） | 5–10KB | 设计文档 §10.4"单实例 + 显隐"不销毁重建 |
| 中文字体子集（flash） | 0.5–1MB | 不占 RAM；16MB flash 充裕 |
| UI 合计峰值 | **60–80KB** | 与音频（Opus 10–20KB + TTS 8–16KB + I2S 2–4KB）、NimBLE、proto 队列并存 |
| 整机目标 | **<200KB 峰值，<70% SRAM（≈280KB）** | 设计文档 §13 / FW-F 验收 |

风险余量充足。若 FW-A 实测超预算，降级顺序：① 单缓冲 240×20（9.6KB）；② `LV_ANIM_OFF` 关全屏动画只留局部；③ 对象静态化 + 去掉卡片动画；④ **最后手段**：列表屏改用 WouoUI 式自绘直接渲染（仅列表一屏），保留 LVGL 于设置/master——不推荐，因引入双渲染管线，仅作极端预案。

### 4.3 可借鉴 WouoUI 的点（零成本）

- 动画手感参考：LVGL `lv_anim` 的 `lv_anim_path_overshoot` / 自定义 bezier 曲线，按 WouoUI 的"可打断 + 分类权重"调参，让翻页/长按菜单/弹窗手感接近"丝滑菜单"。
- 长按视觉反馈（500–700ms 背景加深/波纹）在 LVGL 用 `lv_style` 过渡 + 定时器即可实现。

### 4.4 若仍坚持 WouoUI（不推荐，仅供决策留痕）

若因极端 RAM 约束必须自研，三种模式到 WouoUI 模型的映射与代价：

| 模式 | WouoUI 模型映射 | 需要额外实现 |
| --- | --- | --- |
| 列表模式 | 单列列表 → 需扩展为「4 卡片/页 + 页点 + 垂直翻页」 | 卡片网格渲染、翻页、长按菜单、toast、空态 |
| 设置模式 | 原生契合：`~`数值、`+`多选、`=`单选 + 弹窗 | 滑块（WouoUI 无滑块，用弹窗步进代替，体验降级） |
| master 语音 | 无对应物（静态菜单模型） | 状态大字、波形/留白、**1 行实时字幕需自建滚动文本** |

CJK 策略（WouoUI 路线）：换 TFT_eSPI/LovyanGFX 后端后，用 `lv_font_conv`（LVGL 工具链）输出对应格式的中文子集字库，或自写点阵字模生成脚本；无现成集成，属新增工作。

代价汇总：换后端、重写渲染循环、自建触摸/手势、扩展列表模型、自建动态文本与 CJK 管线——等价于自研一个"LVGL 的功能子集"，且无文档/协议/生态支撑。
