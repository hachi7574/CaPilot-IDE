### C3 — `acp_prompt` 双路径（**CONFIRMED**）

```rust

    return Err(format!("ACP session not found: {id}"));
}
acp_bridge.prompt_async(id, text); // 立即 Ok(())

```

| 情况 | FE await | 错误上屏 |
| --- | --- | --- |
| bridge 无 session | throw → Composer catch | **仅 console** |
| bridge 有 session，模型/限流失败 | Ok 立即返回 | 依赖 `prompt_async` → `AcpEvent::Error` + `useAcpEvents`（**新二进制才有 humanize/fallback**） |

phase5 已在 async 失败路径 `emit Error`；**不能**覆盖 sync not-found，也**不能**覆盖旧包。

### D — live 默认 true + resume 短路（**CONFIRMED · blocker 组件**）

```ts
// emptyAcpSession
live: true  // ← 语义是「已连接」，默认却 true

// ensureAgentChannel ACP
if (s.acpSessions.get(agentId)?.live) return false; // 不 resume
```

- `live=false` 仅见：`dropAgentChannel` / 关项目休眠等；**未见** host 进程死亡 → 自动 `live=false`。
- 场景：spawn 后 `markAcpLive` → GUI 重启或 daemon 侧 ACP 进程不在 → 若内存/恢复路径把 session 标 live，或 stale live 残留 → **跳过 resume** → `acp_prompt` not found → C1 静默。
- 冷恢复：无 `acpSessions` 条目时 `?.live` 为 undefined → 会走 `agent_resume`（相对安全）。危险在 **live 粘 true** 与 **先乐观后失败**。
- `AcpSessionPanel`：`if (session?.live) return` 同样跳过 ensure。
